1. Anonymous Functions

Anonymous Functions

Anonymous functions are functions without a name!

When to use them:

  • When the function is very short and you need it only once

  • When another function (like those in the apply() family) expects another function as input

Anonymous Functions Syntax

We have the following function:

add <- function(x) {
  return(x + 3)
}
add(2)

Now we rewrite it as an anonymous function: no name, one line, and call it directly:

(function(x) {x + 3})(2)

Often anonymous functions are written without the {}:

(function(x) x + 3)(2)

Or with the \(x) shortcut (R 4.1+):

(\(x) x + 3)(2)

Anonymous Functions Syntax

This is the same function as before but now we pass a vector as input rather than a single number:

add <- function(x) {
  return(x + 3) }
add(c(1,2,3))

To rewrite it as anonymous function, the following code won’t work: what are we forgetting?

(function(x) x + 3) c(1, 2, 3)

We are forgetting the second set of ( ): the first ( ) wraps the function; the second ( ) calls it, just like add(2) in regular functions

Anonymous Functions with sapply() and lapply()

You can also rewrite the previous code using sapply() or lapply(). Remember them from last time? They can be used instead of for loops in R.

Both belong to the apply() family and have the same structure:

lapply(X, FUN)
sapply(X, FUN)
  • X is a vector or list (the input)
  • FUN is a function to apply to each element of X

They both loop through the elements of X, apply FUN to each element…

Anonymous Functions with sapply() and lapply()

…But then differ in how they return the result:

  • lapply() (“list apply”) always returns a list
  • sapply() (“simplify apply”) tries to simplify the result to a vector; if it can’t, it returns a list
# previous anonymous function
(function(x) x + 3) (c(1,2,3))

# rewritten with sapply
sapply(c(1,2,3), function(x) x + 3)
sapply(c(1,2,3), \(x) x + 3)

# re-written with lapply
lapply(c(1,2,3), function(x) x + 3)
lapply(c(1,2,3), \(x) x + 3)

Tip: sapply() is popular because usually returns a vector, but sometimes can be a matrix or a list. If you need a predictable output, use map_*() from purrr

Anonymous Functions with sapply() and lapply()

Here’s an anonymous function for calculating the mean of a vector x as (sum / length)

In this example, the input x is each element of the list l:

l <- list(1:5, 5:7)

# lapply: returns a list (3 and 6)
lapply(l, function(x) sum(x) / length(x))
lapply(l, \(x) sum(x) / length(x))

# sapply: returns a vector, c(3, 6)
sapply(l, function(x) sum(x) / length(x))
sapply(l, \(x) sum(x) / length(x))

The function runs twice: first with x = 1:5, then with x = 5:7.

Anonymous Functions with purrr

We can write anonymous function also with the purrr package map_* family from last lecture.

Same function as before, adding 3 to each element of the input:

add <- function(x) {
  x + 3
}
add(c(1,2,3))

Rewritten with purrr in three ways:

library(purrr)

# map_dbl: like sapply, but always returns a double vector
map_dbl(c(1, 2, 3), function(x) x + 3)  # option 1: base R syntax
map_dbl(c(1, 2, 3), \(x) x + 3)         # option 2: base R shorthand (R 4.1+)
map_dbl(c(1, 2, 3), ~ .x + 3)           # option 3: purrr-specific syntax

# map: like lapply, always returns a list
map(c(1, 2, 3), function(x) x + 3)
map(c(1, 2, 3), \(x) x + 3)
map(c(1, 2, 3), ~ .x + 3)

Options 1 and 2 work anywhere in R; option 3 (~ .x) only works inside purrr and other tidyverse functions.

Anonymous Functions: Common uses

Count missing values in each column:

library(palmerpenguins); library(purrr); library(dplyr)

sapply(penguins, \(x) sum(is.na(x)))                              # base R: named vector
map_int(penguins, \(x) sum(is.na(x)))                             # purrr: named integer vector
penguins |> summarise(across(everything(), \(x) sum(is.na(x))))   # dplyr: one-row data frame

Compute the mean of several columns by group:

penguins |>
  group_by(species) |>
  summarise(across(bill_length_mm:body_mass_g, \(x) mean(x, na.rm = TRUE)))
# summarise(across(bill_length_mm:body_mass_g, function(x) mean(x, na.rm = TRUE)))

Anonymous Functions Summary

  • Three ways to write them: function(x) and \(x) work anywhere in R; ~ .x only works in purrr
  • You will mostly use them with apply and map, but anonymous functions work anywhere a function takes another function as input, e.g., across(x, function(x) x + 3))
  • When to use one: for a short, simple operation you need only once
  • When not to use one: if it’s long, complex, or used more than once, give it a name

2. Documenting your function

Functions should be well-documented! How?

Each function should include:

  • A one-sentence description of what it does
  • Its arguments, with their data types (denoted with Args: or @param)
  • Its return value (denoted with Returns: or @return)

Write your documentation yourself first

If you can’t describe your function in one sentence, revisit the function. If you use AI, use it to polish your draft, not to start it.

Document your function: Example 1

#'  Calculate the sum of a numeric vector
#' 
#' @param vector A numeric vector
#' @return A single number: the sum of the elements of `vector`

my_sum <- function(vector) {
  total <- 0
  for (i in seq_along(vector)) {
    total <- total + vector[i]
  }
  return(total)
}

Document your function: Example 1

This is the roxygen2 format: In RStudio, place your cursor in a function and use Code → Insert Roxygen Skeleton

#' Title
#'
#' @param vector 
#'
#' @returns
#' @export
#'
#' @examples

my_sum <- function(vector) {
  total <- 0
  for (i in seq_along(vector)) {
    total <- total + vector[i]
  }
  return(total)
}

Document your function: Example 2

my_sum <- function(vector) {
  # Calculates the sum of all elements in a numeric vector.
  #
  # Args:
  #   vector: a numeric vector whose elements will be summed.
  #
  # Returns:
  #   A single number: the sum of the elements of vector.
  #
  # Example:
  #   x <- c(3, 1, 4)
  #   my_sum(x)

  total <- 0
  for (i in seq_along(vector)) {
    total <- total + vector[i]
  }
  return(total)
}

Document your function: Example 3

Example from Google’s R Style Guide here

CalculateSampleCovariance <- function(x, y, verbose = TRUE) {
  # Computes the sample covariance between two vectors.
  #
  # Args:
  #   x: One of two vectors whose sample covariance is to be calculated.
  #   y: The other vector. x and y must have the same length, greater than one,
  #      with no missing values.
  #   verbose: If TRUE, prints sample covariance; if not, not. Default is TRUE.
  #
  # Returns:
  #   The sample covariance between x and y.
  
  n <- length(x)
  if (n <= 1 || n != length(y)) {
    stop("Arguments x and y have different lengths: ",
         length(x), " and ", length(y), ".")
  }
  if (TRUE %in% is.na(x) || TRUE %in% is.na(y)) {
    stop(" Arguments x and y must not have missing values.")
  }
  covariance <- var(x, y)
  if (verbose)
    cat("Covariance = ", round(covariance, 4), ".\n", sep = "")
  return(covariance)
}

3. Writing functions with the tidyverse

Functions and {{ }}

You can write custom functions and use them together with dplyr or ggplot2 functions!

You need the following elements:

  • syntax to write a custom function
  • special operators that allow R to evaluate your custom functions correctly:
    • bang-bang !! with enquo() (this is the old method)
    • curly-curly or embracing { } (this the most common method)

Check Chapter 25 for more https://r4ds.hadley.nz/functions.html

Functions and {{ }}

We create a data frame of age and height of 5 individuals:

library(dplyr)

df <- tibble(age = c(10, 12, 13, 14, 10), 
             height = c(110, 140, 155, 170, 130))
df
# A tibble: 5 × 2
    age height
  <dbl>  <dbl>
1    10    110
2    12    140
3    13    155
4    14    170
5    10    130

Functions and {{ }}

In this example, we use summarize() from dplyr to compute the mean and standard deviation on the column age of this data frame:

df |>
  summarize(mean_age = mean(age),
            sd_age = sd(age))
# A tibble: 1 × 2
  mean_age sd_age
     <dbl>  <dbl>
1     11.8   1.79

Functions and {{ }}

Let’s try re-writing the previous code as a function without the embracing:

custom_summary <- function(data, col) {
  data |>
    summarize(mean_value = mean(col),
              sd_value = sd(col))
}

custom_summary(df, age)
Error in `summarize()`:
ℹ In argument: `mean_value = mean(col)`.
Caused by error:
! object 'age' not found

We are getting an error because dplyr looks for a column literally called col, which doesn’t exist in df!

Functions and {{ }}

Embracing an argument means wrapping it in double braces:

custom_summary <- function(data, col) {
  data |>
    summarize(mean_value = mean({{ col }}),
              sd_value = sd({{ col }}))
}

custom_summary(df, age)
# A tibble: 1 × 2
  mean_value sd_value
       <dbl>    <dbl>
1       11.8     1.79

Embracing tells dplyr to use the column stored inside the argument age, not a column named col

How to remember it

Our book suggests thinking of { } as looking down a tunnel: { var } makes dplyr look inside var rather than for a column called var.

Embracing multiple columns

Pass several columns at once by embracing them inside across():

custom_summary <- function(data, cols) {
  data |>
    summarize(across({{ cols }}, list(mean = mean, sd = sd)))
}

custom_summary(df, c(age, height))
# A tibble: 1 × 4
  age_mean age_sd height_mean height_sd
     <dbl>  <dbl>       <dbl>     <dbl>
1     11.8   1.79         141      23.0

The output has clearly labeled columns: age_mean, age_sd, height_mean, height_sd.

When do you need embracing {{ }} when writing a function?

Whenever your function passes a column name to a tidyverse function that uses “tidy evaluation.” There are two main types (see Chapter 25 of the readings for details):

  • Data masking: functions that compute with columns
    • e.g., mutate(), filter(), summarize(), arrange(), group_by() in dplyr, and aes() in ggplot2
  • Tidy selection: functions that choose columns
    • e.g., select(), rename(), relocate(), across(), pivot_longer()

How to tell which one?

Check the help page: arguments are labeled <data-masking> or <tidy-select>.
