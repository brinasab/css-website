2. Key dplyr functions

The package dplyr has many functions

These functions:

  • Act like verbs in a sentence: they say what to do with the data (e.g., filter, summarize, etc. )
  • Can be combined to perform complex tasks

Today we learn the following dplyr functions

function() What it does
filter() Keeps rows based on conditions
summarize() Calculates summary statistics for each group (e.g., mean, sum, count)
group_by() Groups data by one or more variables
count() Counts the unique values of one or more variables
mutate() Creates new columns or modifies existing ones

Must-Know Verbs

There are many verbs in dplyr, but don’t need to memorize all of them. This week we learn the most important. Memorize those we cover today and next class and look up the rest as needed at https://dplyr.tidyverse.org/

filter()

Keeps only the rows that match a condition

For example, this code keeps only penguins whose species is Adelie:

filter(penguins, species == "Adelie")

filter()

  • works on rows
  • keeps rows where the condition is TRUE
  • is often used with logical operators like ==, !=, >, <, &, |

Logical operators in filter()

R logical operators return TRUE or FALSE:

x == y    # is x equal to y? (TRUE or FALSE)
x != y    # is x not equal to y? 
x < y     # is x less than than y?
x <= y    # is x less than or equal to y?
y > x     # is y greater than x?
y >=      # is y greater than or equal y?


Examples:

adelie <- filter(penguins, species == "Adelie")
no_adelie <- filter(penguins, species != "Adelie")
heavy <- filter(penguins, body_mass_g > 4500)

Logical operators in filter()

R logical operators can combine multiple TRUE/FALSE conditions:

x | y     # EITHER x OR y has to be TRUE
x & y     # BOTH x AND y have to be TRUE 
x &! y    # x is TRUE AND y is FALSE


Example use of | operator. What does this code return?

filter(penguins, species == "Adelie" | species == "Chinstrap")


Example use of & operator. What does this code return?

filter(penguins, species == "Adelie" & species == "Chinstrap")


Two Ways to Write “OR”

Use OR to keep rows where a variable is equal to one value OR another value. In R, you can write this in two equivalent ways:


Option 1: use | to spell out each condition

filter(penguins, species == "Adelie" | species == "Chinstrap")


Option 2: use %in% to check whether a value is in a list of allowed values

filter(penguins, species %in% c("Adelie", "Chinstrap"))

summarize()

Reduces the data to summary values

For example, this code calculates the average body mass across all penguins:

summarize(penguins, avg_mass = mean(body_mass_g, na.rm = TRUE))

summarize()

  • calculates summary statistics
  • usually returns fewer rows than the original data
  • often uses functions like mean(), median(), n()

Examples of summarize()

# Example 1: only summarize 
summarize(penguins,
  body_mass_mean = mean(body_mass_g, na.rm = TRUE),
  body_mass_sd = sd(body_mass_g, na.rm = TRUE),
  n = n()  # n = nrow(penguins)
)

# Example 2: combine filter with summarize
penguins |> 
  filter(species == "Gentoo") |> 
  summarize(body_mass_mean = mean(body_mass_g, na.rm = TRUE),
            body_mass_sd = sd(body_mass_g, na.rm = TRUE),
            n = n())

group_by()

Temporarily group the data, so the next function runs within each group

For example, this code groups the data by species, so summarize() calculates the average body mass for each species separately:

grouped <- group_by(penguins, species)
summarize(grouped, avg_mass = mean(body_mass_g, na.rm = TRUE))

group_by()

  • uses one or more columns (e.g., variables) to define groups
  • does not change the data itself: changes how the next function treats the data
  • often used before summarize()and fiter()
  • often used with categorical variables

Examples of group_by()

# group by alone? not that useful
grouped <- group_by(penguins, island, sex)
summarize(grouped, avg_mass = mean(body_mass_g, na.rm = TRUE))

# group by and calculate mean body mass
grouped <- group_by(penguins, island, sex)
summarize(grouped, avg_mass = mean(body_mass_g, na.rm = TRUE))

# group by and count
grouped <- group_by(penguins, island, sex)
count(grouped)

count()

Counts the number of observations in each group

For example, this code counts how many penguins belong to each species:

count(penguins, species)

count()

  • Counts rows within each group
  • Works with categorical and numerical variables, but most useful for categorical
  • Is a shortcut for group_by() + summarize(n = n())

Using count() as shortcut

# total penguins by sex without count
penguins |> 
  group_by(sex) |> 
  summarize(total = n())

# total penguins by sex with count
penguins |>
  count(sex)

mutate()

Creates new columns or modifies existing ones

For example, this code creates a new column converting body mass from grams to kilograms:

penguins <- mutate(penguins, body_mass_kg = body_mass_g / 1000)

mutate()

  • works on columns
  • creates new variables or modifies existing ones
  • it does not reduce the dimensions of the original data

Should we Filter or Group First?

Q3: What is the average body mass for Adelie penguins by sex?


  • ✅ Filter for Adelie, then group by sex, then summarize
  • Group by sex, then filter for Adelie, then summarize
  • Group by species, filter for Adelie, then group by sex, then summarize
  • Filter by both species and sex, then group, then summarize
  • Group by both species and sex, then summarize, then filter

The first is the best approach in this case. The other approaches are all correct (try them out!), but are less readable or do more work than needed.

The next slide compares the first two approaches, which are the most common.


Should we Filter or Group First?

Q3: What is the average body mass for Adelie penguins by sex?


Filter → Group (Best here)

  • Filter first to keep only Adelie penguins
    → reduces rows right away
  • Group the filtered data by sex
    → only relevant data is grouped
  • Summarize to get average

Group → Filter (Works but not best here)

  • Group all penguins by sex
    → includes extra, unneeded data
  • Filter to keep only Adelie penguins
    → discards part of what was grouped
  • Summarize to get average

3. Pipes %>% or |>

Pipes to Chain Commands

Pipes allow you to write a sequence of operations by passing the result of one function into the next making your code more readable and logical. Compare these two versions of the same code to calculate the average body mass for Adelie penguins by island.

Without pipes:

adelie <- filter(penguins, species == "Adelie")
adelie_island <- group_by(adelie, island)
adelie_avg_mass_island <- summarize(adelie_island, body_mass = mean(body_mass_g, na.rm = TRUE))

With pipes:

adelie_avg_mass_island <- penguins |>
  filter(species == "Adelie") |>
  group_by(island) |>
  summarize(body_mass = mean(body_mass_g, na.rm = TRUE))

Pipes are the best! But there are multiple ways to write R code

Pipes are great and our ultimate goal. But there are several ways to write the same R code.

In fact, R didn’t have pipes for a long time!

Let’s compare different ways to write the same code…

Four Different Options to Code This Task

Task: Calculate the average body mass for Adelie penguins by island.


Strategy: Break Down the Task Before You Code it!

  • Identify data and variable needed
  • Filter the data for rows where species is Adelie
  • Group the filtered data by island
  • Calculate the average body mass for each group


Option 1: Save each step in a new data frame

penguins_adelie <- filter(penguins, species == "Adelie")
penguins_adelie_island <- group_by(penguins_adelie, island)
penguins_final <- summarize(penguins_adelie_island, 
                            body_mass = mean(body_mass_g, na.rm = TRUE))
print(penguins_final)
# A tibble: 3 × 2
  island    body_mass
  <fct>         <dbl>
1 Biscoe        3710.
2 Dream         3688.
3 Torgersen     3706.


✅ This is valid code.

⚠️ Drawback: You must save each intermediate object. This can clutter your environment, increase R memory usage, and make your code more prone to typos. Shorter names for each step might reduce typos but sacrifice readability.


Option 2: Replace the original data frame

penguins <- filter(penguins, species == "Adelie")
penguins <- group_by(penguins, island)
penguins <- summarize(penguins, body_mass = mean(body_mass_g, na.rm = TRUE))
print(penguins)
# A tibble: 3 × 2
  island    body_mass
  <fct>         <dbl>
1 Biscoe        3710.
2 Dream         3688.
3 Torgersen     3706.


✅ This also works, but it’s not good practice.

⚠️ Drawback: It overwrites the original dataset. If something goes wrong, you need to re-run everything.

Warning

This approach is risky — especially when working with important datasets. Always keep a copy of your original data before modifying it.


Option 3: Function composition

data(penguins)
summarize(group_by(filter(penguins, species == "Adelie"), island), 
          body_mass = mean(body_mass_g, na.rm = TRUE))
# A tibble: 3 × 2
  island    body_mass
  <fct>         <dbl>
1 Biscoe        3710.
2 Dream         3688.
3 Torgersen     3706.


✅ This also works, and some people like this style.

⚠️ Drawback: It’s harder to read and debug. You must follow it from the inside out, which makes it harder to read for humans. If something breaks, it’s difficult to isolate where the error is happening as you can’t easily inspect intermediate results.


Option 4: Pipes (The Winner!)

penguins |>
  filter(species == "Adelie") |>
  group_by(island) |>
  summarize(body_mass = mean(body_mass_g, na.rm = TRUE))
# A tibble: 3 × 2
  island    body_mass
  <fct>         <dbl>
1 Biscoe        3710.
2 Dream         3688.
3 Torgersen     3706.


✅ This is valid and readable code without the drawbacks of the previous options.

💡 Why pipes? The pipe operator passes the result of one function to the next, making your code easier to read. Pipes emphasize actions, not object names and you can read the code like a recipe:

Start with the dataset → filter for Adelie penguins → group by island → summarize body mass

Common Pipe Errors: Example 1

What’s wrong with this code?

Before we debug it, let’s first explain what the code is trying to do conceptually.

Invalid code

delays <- flights %>% 
  by_dest <- group_by(dest) %>% 
  delay <- summarize(
    count = n(),
    delay = mean(arr_delay, na.rm = TRUE)) %>% 
  d <- filter(count > 20)

Common Pipe Errors: Example 1

Invalid code

delays <- flights %>% 
  by_dest <- group_by(dest) %>% 
  delay <- summarize(
    count = n(),
    delay = mean(arr_delay, na.rm = TRUE)) %>% 
  d <- filter(count > 20)
  • Take the flights dataset
  • Group flights by destination, using the variable dest
  • Count the delayed flights and store the result in a new variable called count
  • Calculate the average arrival delay, using arr_delay, and store the result in a new variable called delay
  • Remove destinations with less than 20 flights. Question: Why filter(count > 20) to remove destinations with fewer than 20 flights?

Common Pipe Errors: Example 1

What’s wrong with this code?

Invalid code

delays <- flights %>% 
  by_dest <- group_by(dest) %>% 
  delay <- summarize(
    count = n(),
    delay = mean(arr_delay, na.rm = TRUE)) %>% 
  d <- filter(count > 20)

Correct code

delays <- flights %>%
  group_by(dest) %>%
  summarize(
    count = n(),
    delay = mean(arr_delay, na.rm = TRUE)) %>%
  filter(count > 20)


Important

Don’t assign anything inside a pipe. Use <- only at the start, if you want to save the final result. Do not use it between steps.
