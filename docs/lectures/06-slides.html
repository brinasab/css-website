Combining Verbs with the Pipe

Often we want to chain verbs together with the pipe |>. This combination comes up frequently:

Key combo: filter() + group_by() + summarize()

penguins |> 
  filter(species != "Gentoo") |> 
  group_by(island) |> 
  summarize(body_mass_mean = mean(body_mass_g, na.rm = TRUE))

You can also narrow down columns first with select(), then repeat the same combo

penguins |> 
  select(species, island, body_mass_g) |> 
  filter(species != "Gentoo") |> 
  group_by(island) |> 
  summarize(body_mass_mean = mean(body_mass_g, na.rm = TRUE))

2. Introduce new dplyr functions (aka “verbs”)

Today we learn the following dplyr verbs

function() What it does
select() Chooses specific columns
relocate() Reorders columns
arrange() Reorders rows based on values in specified columns
distinct() Returns unique rows based on columns
pull() Extracts a single column as a vector
across() Applies the same operation to multiple columns at once

Must-Know Verbs

There are many verbs in dplyr, but don’t need to memorize all of them. This week we learn the most important. Memorize those we cover this week and look up the rest https://dplyr.tidyverse.org/

select()

Keeps only the columns (e.g., variables) we want

For example, this code keeps only species, island, and body_mass_g:

penguin_subset <- select(penguins, species, island, body_mass_g)

select()

  • works on columns
  • keeps variables
  • useful when a dataset has more columns than we need, else you can skip it

Examples of select()

# select two specific variables using their names
select(penguins, species, body_mass_g)

# select all variables except two using the minus sign
select(penguins, -year, -island)

# select a range of contiguous/adjacent variables
select(penguins, species:bill_length_mm)

# select all variables except a range of contiguous ones
select(penguins, -(species:island))

# select all variables that start with
select(penguins, starts_with("bill"))

# select all variables that end with
select(penguins, ends_with("mm"))

relocate()

Moves columns (e.g., variables) to a new position in the dataset

For example, this code moves body_mass_g to the front of the dataset:

penguins_moved <- relocate(penguins, body_mass_g)

To place a column somewhere specific, use .before or .after:

penguins_moved <- relocate(penguins, body_mass_g, .after = species)

relocate()

  • works on columns
  • changes the order of variables, but does not add or remove any
  • moves columns to the front by default; use .before or .after to choose a spot
  • useful when the variables we care about most are buried at the end of a wide dataset

Examples of relocate()

penguins |> relocate(year, sex)

penguins |> relocate(year, .after = island)

arrange()

Sorts the rows (e.g., observations) by the values of one or more columns

For example, this code sorts penguins from lightest to heaviest by body_mass_g:

penguins_sorted <- arrange(penguins, body_mass_g)

To sort from heaviest to lightest, wrap the column in desc():

penguins_sorted_desc <- arrange(penguins, desc(body_mass_g))

arrange()

  • works on rows
  • changes the order of observations, but does not add or remove any
  • sorts in ascending order by default; use desc() for descending
  • useful for finding the largest or smallest values, or making a table easier to read

Exampels of arrange()

penguins |> arrange(desc(bill_length_mm))

penguins |>
  select(species, contains("bill")) |>
  filter(!species == "Adelie") |>
  arrange(desc(bill_length_mm)) 

penguins |>
  select(species, contains("bill")) |>
  filter(!species == "Adelie") |> 
  arrange(desc(species), bill_length_mm)

distinct()

Keeps only the unique rows (e.g., removes duplicate observations)

For example, this code returns each unique combination of species and island:

species_islands <- distinct(penguins, species, island)

To keep all the other columns too, add .keep_all = TRUE:

species_islands_full <- distinct(penguins, species, island, .keep_all = TRUE)

distinct()

  • works on rows
  • removes duplicates, keeping the first occurrence of each unique row
  • useful for spotting duplicate entries or listing the unique values or combinations in our data

Examples of distinct()

# not too handy alone
penguins |>
  distinct()

# better with specific columns
penguins |>
  distinct(species, island)

# keep all columns in the resulting data frame
penguins |>
  distinct(species, island, .keep_all = TRUE)

Note: gives back a dataframe with only unique combinations of those columns https://dplyr.tidyverse.org/reference/distinct.html

pull()

Extracts a single column (e.g., variable) as a vector

For example, this code pulls out body_mass_g as a plain vector of numbers:

body_masses <- pull(penguins, body_mass_g)
class(body_masses)

pull()

  • works on columns
  • returns a vector, not a data frame
  • similar to penguins$body_mass_g, but works smoothly inside a pipe
  • useful when you need the data to be a vector

Examples of pull()

We want to keep only the penguins that are heavier than the average penguin.

This won’t work

avg_mass <- penguins |>
  summarise(avg = mean(body_mass_g, na.rm = TRUE))

penguins |> filter(body_mass_g > avg_mass)

With pull it will work

avg_mass <- penguins |>
  summarise(avg = mean(body_mass_g, na.rm = TRUE)) |> pull(avg)

penguins |> filter(body_mass_g > avg_mass)

Why does pull() make the difference in the previous example?

Slide added after class discussion: use class() to see what avg_mass is in each case!

Without pull

avg_mass <- penguins |>
  summarise(avg = mean(body_mass_g, na.rm = TRUE))
penguins |> filter(body_mass_g > avg_mass)
class(avg_mass)  # returns "tbl" for tibble or dataframe

With pull

avg_mass <- penguins |>
  summarise(avg = mean(body_mass_g, na.rm = TRUE)) |> pull(avg)
penguins |> filter(body_mass_g > avg_mass)
class(avg_mass) # returns "numeric" for numeric vector

The verb summarize() always returns a tibble (a data frame), even when it holds a single value. So without pull(), the comparison becomes filter(body_mass_g > <1 x 1 tibble>), which does not work in R because comparison operators like > inside filter() need vectors (and in R, a single number is still a vector)

across()

Applies the same function to several columns (e.g., variables) at once

Unlike the other verbs, across() isn’t used on its own. It goes inside another verb like summarise() or mutate().

across()

  • works on columns
  • is a helper, not a stand-alone verb; it lives inside summarise() or mutate()
  • takes two main parts: which columns to use, and what function to apply to them
  • columns can be chosen by name, with helpers like starts_with(), or by type with where()
  • useful when we’d otherwise repeat the same code over and over for many columns

Examples of across()

Compare the same code with and without across() with numerical variables:

# mean for a bunch of variables without across
penguins |>
  summarize(
    mean_bill_length_mm = mean(bill_length_mm, na.rm = TRUE),
    mean_bill_depth_mm = mean(bill_depth_mm, na.rm = TRUE),
    mean_flipper_length_mm = mean(flipper_length_mm, na.rm = TRUE),
    mean_body_mass_g = mean(body_mass_g, na.rm = TRUE)
  )

# same operation with across
penguins |>
  summarize(
    across(
      c(bill_length_mm, bill_depth_mm, flipper_length_mm, body_mass_g), 
      ~ mean(.x, na.rm = TRUE)  # function(x) mean(x, na.rm = TRUE)
    ))

Examples of across()

Compare the same code with and without across() with categorical variables:

# number of distinct entries for columns without across
penguins |>
  summarise(distinct_species = n_distinct(species),
            distinct_island = n_distinct(island),
            distinct_year = n_distinct(year))

# number of distinct entries for columns with across
penguins |>
  summarise(across(c(species, island, year), 
                   n_distinct))

# the opposite
penguins |>
  summarise(across(-c(species, island, year), 
                   n_distinct))

# everything
penguins |>
  summarise(across(everything(), 
                   n_distinct))

3. Data Cleaning

Data Cleaning: Renaming & Recoding Variables

A Few More dplyr Functions

We now introduce a few more dplyr functions: rename(), recode(), and case_when().

We introduce them here, in the context of renaming and recoding variables, because that’s how they’re typically used in practice.

Note

recode() and case_when() only work on a single column’s values, so they’re always used inside mutate()

Definitions of Rename and Recode

Rename: change variable names (column names)

Recode: change values/levels of categorical variables (column values; e.g., inside a column)

Uses of Rename and Recode

When might you need to rename variables or recode their values?

  • You are cleaning data
    • The variable name has issues: Flipper Length (mm) → flipper_length_mm
    • You need to standardize values: "Good" and "GOOD" → "good"
    • Etc.
  • You are preparing data for modeling or visualization
    • You want to recode "FEMALE"/"MALE" to 0/1 for a regression model
    • Etc.

Renaming Variables with rename

To change variable names (column names) the most common way is by using rename()

Change the name of the variable studyName to study_name:

# check before renaming
str(penguins_raw)
penguins_raw %>% select(studyName)

# rename
penguins_raw %>% rename(study_name = studyName)   # new = old

# remember to save to keep changes
p <- penguins_raw %>% rename(study_name = studyName)
p %>% select(study_name)

Recoding Variables Method 1: with mutate + recode

To recode variables (e.g. change variable values), we learn two approaches.

Let’s illustrate both methods by using the variable Sex and change its values: MALE into 1, FEMALE into 0.

Method 1:

# check before recoding
penguins_raw %>% count(Sex)

# mutate + recode
p <- penguins_raw %>%
  mutate(sex = recode(Sex, "MALE" = 1, "FEMALE" = 0))

# compare
penguins_raw %>% count(Sex)
p %>% count(sex)

Recoding Variables Method 2: with mutate + case_when

Method 2:

# mutate + case_when
penguins_raw %>%
  mutate(Sex = case_when(Sex == "MALE" ~ 1,
                         Sex == "FEMALE" ~ 0,
                         TRUE ~ NA_real_))
  
# like for method 1 (previous code) save results to keep changes and compare

With case_when() each logical condition ~ value pair acts like if → then

  • for each row, R looks if the condition is TRUE: “If you find the value MALE in Sex, then convert it to 1”
  • TRUE ~ NA_real_ tells R: “If no previous condition was met, then return NA as as a number”

Note the code in this slide overwrites the original Sex column (e.g., variable). To keep it, give the new column a different name, like sex (lowercase). You can do this both Method 1 and Method 2.

The Role of mutate in Recoding

The dplry verb mutate has many uses: create new columns or modify existing columns values.

Note

For recoding, use mutate + recode or mutate + case_when, because the goal is changing the column’s values:

  • Method 1: mutate(Sex = recode(Sex, "MALE" = 1, "FEMALE" = 0))
  • Method 2: mutate(Sex = case_when(sex == "MALE" ~ 1, sex == "FEMALE" ~ 0))

Which method is “best”? It depends, but method 2 is more popular (flexible/powerful)!

Rename vs Recode: Syntax Reference

Function What It Changes Syntax + Example Tips
rename() Column names rename(new_name = old_name)
rename(notes = Comments)		 No quotes around variable names
recode() Column values recode(variable, "old" = new)
recode(Sex, "MALE" = 1)		 Check function doc to see when quotes are needed
case_when() Column values case_when(variable == "old" ~ new)
case_when(Sex == "MALE" ~ 1)		 Check function doc to see when quotes are needed

Data Cleaning: Syntactic vs. Non-syntactic Variable Names

Syntactic (Valid) Variable Names in R

Valid Names in R:

  • Use letters, numbers, and the symbols . or _
  • But cannot start with a number or symbol

Examples of Valid Names:

flipper_length_mm
flipper.length.mm
flipper.length_mm     # valid but poor style
FlipperLengthMm       # valid but poor style

Non-Syntactic (Invalid) Variable Names in R

What Makes a Name Invalid:

  • Contains spaces or symbols
  • Starts with a number or symbol
  • Uses reserved words (e.g., TRUE, NULL, if, function)
  • Type ?Reserved in the Console for the full list

Examples of Invalid Names:

Flipper Length (mm)
@_flipper_length_mm
flipper_ length_mm
flipper-length-mm
.flipper.length.mm

Tip

How to Handle Non-syntactic Names, and Why It Matters

You should avoid creating non-syntactic names, BUT you’ll often encounter them, especially in datasets not created in R (Excel or other sources). If you don’t handle them properly, R will throw errors when you try to use them.

What to Do:

1. Use backticks to refer to them (e.g., `Flipper Length (mm)`)
2. Use rename() to change them to syntactic names

Non-syntactic names will break code if you forget to wrape them in backticks, so renaming avoids issues.

Working with Non-syntactic Names in Practice

Imagine you are working on political ideology by country data, assembled by someone else. The data are in Excel and when you imported them in R they look like this:

df <- tibble(country = c("Italy", "Germany", "France", "Italy", "United States"),
            `4 ideology` = c("communism", "fascism", "anarchism", "fascism", "capitalism"))

To use the non-syntactic variable name without changing it and without errors, you must use backticks:

select(df, `4 ideology`)

Then rename that variable to a syntactic name:

df <- rename(df, ideology = `4 ideology`)
