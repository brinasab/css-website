Final Project

HW5 Final Project Overview

Due: Sunday, December 06 by 11:59 PM (Chicago Time)

In this final assignment, you’ll apply the skills learned in the course to a topic of your choice.

Accessing the repo

  1. Go to this link. The first time, click Sign in with GitHub and authorize Classroom 50 (the tool we use to distribute assignments).

  2. Click Accept assignment to create your private hw05 repository on GitHub. Your repository will be named css-hw05-<USERNAME>. Keep the page open until the setup checklist finishes (a few seconds).

  3. Click Open repository to access it.

If the page says “Not a member yet”, accept the invitation to our GitHub organization (check your email, including spam), then click Check again. If it says “This assignment isn’t available to you”, contact the instructor.

Cloning the repo into your Workbench

  1. Log into Workbench and start a new project:
    File > New Project > Version Control > Git

  2. In the Repository URL field:

    • Paste the URL of your GitHub repository. To find the URL, go to your hw05 repo on GitHub, click the green Code button, and copy the SSH or HTTPS link (use the method you configured during setup: Workbench users must select SSH).
    • The project name should auto-fill. If not, type the same name manually (it should match the GitHub repo name).

  3. Choose where to save the project directory locally. Tip: Avoid moving folders after cloning them.

  4. Check the box “Open in new session” (recommended for keeping projects organized).

  5. Click Create Project. This will:

    • Create a new folder on your machine
    • Initialize a Git repository linked to GitHub
    • Open an RStudio Project in a new session

You’ll use this same process to access and set up each homework assignment throughout the course.

Note

The repo you clone for hw05 (your final project) is intentionally empty: you will need to add your own data and code, and push them. See the instructions below for what to submit. Remember to include the knitted .md file(s)!.

Assignment Description

The main goal of the final project is to apply the skills learned in the course to a topic of your choice. Your task is to find data, ask one or more research questions, and answer them descriptively using data and code.

The sections below walk you through the details of each part of the assignment and its main deliverables.

1. Report Instructions

1.1 Report Format

  • Format: the report must be written using a .Rmd file, knitted to.md and .pdf
  • The report must include: Written text, code chunks, code outputs (tables, plots, descriptive stats). Not all code you write is required to go in your report: you may place extra code in a separate R script or Rmd file. If so, mention this in your README.md.
  • Audience: Write your report as if you were preparing a polished analysis for either an academic audience or a professional industry setting.
  • Length: Aim for 800-900 words (minimum 700, maximum 1000).
  • Use of R Markdown Syntax: Use clear headings and subheadings and include a table of contents. Include some of the advanced R Markdown tools covered in class (Lecture 16).

1.2 Report Required Sections

Specifically, your report should include the following sections:

  • Project description
    • Start by explaining what your project is about, its goals, and why it matters.
    • Describe the dataset (number of observations, time period, key variables, data source). Store the data in your repo, if smaller than 100 MB; if larger, see below.
    • State one or more research questions, ideally with social science relevance.
    • State one or more hypothesis or describe what you expect to find and why.
  • Descriptive statistics and plots
    • Include tables (format them with kable) and descriptive statistics (counts, percentages, mean, median, contingency tables, etc.).
    • Include 4 or 5 well-designed plots with clear titles, labels, scales, etc. Use different types of plots (do not use the same plot more than once). Ensure each one matches the underlying variable types.
    • Use code to transform or prepare variables for your plots and analyses when needed (e.g., recoding, standardizing, creating new variables, joining relational tabels, etc.).
    • Describe the main findings of each graph: highlight patterns, discuss possible relationships between variables, note limitations, and suggest directions for future research. We want to hear your explanation and interpretation of the analyses!
    • You are not expected to include statistical models since we did not cover them in the course. Excellent projects can rely entirely on descriptive statistics and the types of plots you did in HW2 and HW3. If you’d like to add models (e.g., regression, ANOVA, etc.), check with me first (see FAQs below).

2. Code Instructions

This course has a strong coding component, so the quality and organization of your code are an important part of the project. Specifically:

  • Library Loading and Data Import
    • Load all required libraries and import your data once, at the top of your Rmd. Do not reload libraries elsewhere.
    • Store the data as .csv into a sub-folder; if data files are larger than 100MB, store somewhere else (see below for details)
  • Data Cleaning, Wrangling, and Tidying
    • Include code needed to prepare your data (renaming, recoding, aggregating, tidying data, joining data etc.). The amount of cleaning will depend on your project, but all projects must include some.
    • If your code for data prep and cleaning is extensive, place it in a separate script or Rmd file (see below).
  • Data Analysis and Plots
    • Include dplyr code for exploring the data with descriptive statistics (summaries, counts, percentages, mean, median, contingency tables, etc.).
    • Include ggplot2 code for 4–5 well-designed plots. Use a variety of plot types and match each to the variable types. If your dataset requires little cleaning, we expect more complex and refined visualizations.
  • Specific Programming Techniques
    • Include at least one user-defined function
    • Include either a loop (or a map/across/apply alternative) OR a conditional statement. If you can’t find a place to use them in your project, check in with us and we’ll help you find one.
  • Code Organization
    • Include only relevant output (e.g., show the head of your dataset, not the full dataset) and follow coding practices from class: clean style, reproducible workflow, and Markdown formatting. Prefer tidyverse functions over base R, where applicable (e.g., use read_csv() instead of read.csv()).
    • Do not put too much code in a single code chunk. Each chunk should do one clear task or sub-task, like loading data, calculate something, making a plot. Shorter chunks make your code easier to read and fix.
    • Extensive cleaning steps or extra plots can go in a separate R script or Rmd. If you do so, in the main report, load the cleaned data and include only the required plots. Store all code in your repository to ensure reproducibility. Let us know the location of any additional code in your README.md.

3. Repo and README.md Instructions

Your repository must include a README.md with the following information:

  • Purpose of the repository: About 3-4 bullet points on what your project is about such as topic, data source, and sample size.

  • List of files: All R scripts and .Rmd files in the repo, organized similarly to this example (use your own file names, and add or remove files as needed):

my-project/
├── README.md
├── data/
│   └── survey.csv
├── scripts/
│   ├── 01_clean_data.R
│   ├── 02_descriptive.R
│   └── 03_make_plots.Rmd
└── report.Rmd

  • Required packages: Any non-basic packages needed to run your code (no need to list tidyverse or rmarkdown).

  • Additional information: Anything else a user needs to understand or replicate your work, like the order to run files or where to get the data.

Tip: Imagine a classmate opening your repo for the first time. Could they understand and run your project using only the README? If so, you’re all set!

FAQs

How do I know if I have “done enough”?

  • First, make sure you’ve met all requirements listed above for the report, code, and README.md.
  • Time to complete will vary by student, project, working style, and level of investment in the project. As a rough benchmark, this assignment should take about as much time as previous assignments.
  • Aim to build on what you’ve learned and push a bit beyond your comfort zone. If you’re unsure whether your plan is enough, check in with us.
  • This assignment should reflect your own work. You may seek advice from people or AI tools, but your code must be written by you, understandable to you, and aligned with our AI policy.

What data should I use?

We encourage you to use social science data; other types of data can work too but check with us first. What matters most is applying the skills you learned to a topic that interests you: the best projects are the ones you are genuinely excited to work on

I can’t think of anything to analyze!

You may use any dataset from class not used in previous homework and or in teaching examples (e.g., penguins, cars, iris datasets are not appropriate). Some options to consider:

  • gun_deaths from library(rcis), or the raw data from FiveThirtyEight (it’s a similar topic but this is different dataset than HW2)
  • Explore the Data Is Plural dataset archive
  • Explore the #TidyTuesday dataset archive

What if my data file is too large?

GitHub does not allow files larger than 100MB. If you try to push one, you’ll get an error and may have to remove the file from your Git history, which is a hassle. Thus:

  • If your data is well under 100MB, include it in your repo.
  • If it is close to or above 100MB, do not include it in your repo. Instead, store it outside GitHub (e.g., Google Drive, remember to give us access) and include a link to it in your README.md.

My idea that doesn’t quite fit the description, what are my options?

You’re welcome to propose a small variation on this project, as long as the core of the assignment stays the same. For example, you might want to use web scraping to get your data, do some text analysis, take on a larger data cleaning task, or run some statistical analyses beyond descriptive statistics. If this sounds like you, email me your idea by Sunday, November 15, and we’ll meet in Week 8 to make a plan.

When we meet, we’ll check that your idea matches the project’s learning goals and your current skills. If it’s a big leap, like doing machine learning with no prior background, we’ll adjust it into something challenging but achievable.

A few things are required for everyone (your README, repo organization, code that you wrote and understand, and some descriptive statistics and plots). Other parts, like the number of plots or how detailed your descriptive statistics are, can be swapped for equivalent work. If we haven’t agreed on a plan, your project should fully meet the guidelines

Submit the Assignment

To submit your assignment on Canvas, follow these steps:

  1. Before the deadline, push the final version of your work to your GitHub repository. Tip: don’t wait until the end to make your first commit; instead stage, commit, and push your work regularly as you go.

    Your GitHub repository should include:

    • All files used to collect your data and produce your analyses, such as R scripts and R Markdown files, plus your data (unless it’s too large; see above)
    • Your README.md
    • Your report as a Rmd file, knitted both as md and pdf (submit all three)
    • The folder that contains all the graphs generated by your .Rmd (this is automatically created when you knit, make sure to push it)

  2. When you’re ready to submit:

    • Copy the URL of your GitHub repository. It will look something like: https://github.com/css-fall26/css-hw05-yourusername
    • Submit that URL on Canvas under HW05. Do not upload any files to Canvas. We only need the repository link. Your repository remains private, only the instructional staff can access it.
